## 一、四份文件的用途

| 文件 | 主要面向对象 | 用途 | 常见使用方式 |
| --- | --- | --- | --- |
| `用户协议.md` | 甲方（客户）及终端用户 | 约定产品使用条件、许可边界、账号与管理员责任、可接受使用、AI 生成内容性质、HR 场景红线、责任限制、期限与终止、争议解决 | 双方签署，或作为主协议附件 / 终端用户点击确认 |
| `隐私政策.md` | 终端用户（客户员工、管理员、求职者等自然人） | 以面向个人、通俗易懂的方式公示收集哪些信息、处理目的、存储位置与期限、第三方共享、安全措施、个人权利行使方式 | 在产品登录页 / 关于页公示，由甲方按其角色对外发布 |
| `数据处理协议-DPA.md` | 甲方与乙方 | 约定个人信息处理的角色划分、处理范围与指令、数据类别与主体、子处理者、技术与组织措施、数据主体请求协助、安全事件通知、删除与备份时滞、跨境传输 | 作为主协议附件，双方签署 |
| `软件许可协议-License.md` | 甲方与乙方 | 约定软件许可授予范围、禁止事项、试用与正式许可差别、期限与到期处理、交付物清单、验收、维护升级、费用、开源组件声明、终止善后 | 双方签署，作为商业交付的核心许可文件 |

另外，仓库根目录的 `LICENSE` 是**仓版权属声明**（不是授权许可证），
`docs/操作手册.md` 是运维操作说明，`CHANGELOG.md` 是版本记录，三者与法律文本需交叉核对事实。

## 二、占位符填写规范

- 统一使用**双花括号** `{{...}}`，例如 `{{甲方名称}}`、`{{乙方名称}}`、`{{产品名}}`、`{{日期}}`。
- 全文检索 `{{` 即可定位所有待填项；提交签署版前应确认**无任何残留占位符**。
- 同一实体在不同文件中必须使用**完全一致**的名称与写法。
- 日期统一写作 `YYYY-MM-DD`（本轮文档基准日期为 2026-11-13）。
- 数值型占位符（坐席数、实例数、可用率、留存期限、通知时限、费用、赔偿上限等）
  必须由业务与法务共同确认，**不得沿用模板默认值或凭空填写**。
- 严禁在模板中写入真实口令、API Key、真实姓名、真实公司名与真实联系方式；
  示例一律使用占位符或 `<token>` 这类示意写法。

## 三、必须由法务逐条审核的条款（重点清单）

以下条款风险较高，**须逐条审核并按需改写**，不得直接沿用模板表述：

1. **责任限制与免责、间接损失排除、赔偿上限**（用户协议、License 协议、DPA）。
2. **知识产权归属**，尤其是模型输出的权利归属与使用边界、客户上传内容与知识库语料的授权链条。
3. **AI 生成内容免责**与**HR 场景红线**（评分 / 匹配仅作辅助参考、禁止自动淘汰候选人）。
4. **第三方共享与跨境**：提示词与文档片段发送至第三方模型厂商这一事实的告知、同意基础与合同安排。
5. **个人信息处理角色划分**（客户作为处理者、我方作为受托处理者），以及全局管理员可见全库数据这一事实对责任边界的影响。
6. **敏感个人信息**（简历中可能包含）的处理依据、单独同意与最小必要范围由谁负责。
7. **未成年人**相关条款的适用性。
8. **数据删除、导出与备份时滞**：历史整卷备份中的副本如何轮转、是否需单独约定。
9. **试用与正式许可、License 到期处理**的技术口径（默认仅提示、是否阻断由双方约定并启用）。
10. **争议解决与适用法律**、管辖 / 仲裁机构的选择。
11. **开源组件声明**与商业许可并存时的交付义务。
12. **现有能力缺口**：无 SSO、无多租户、无自动化「删除用户全部数据」接口、无数据留存自动清理定时任务、
    无异地备份等，是否需作为已知限制由甲方书面确认。
13. **服务级别、维护窗口、安全事件通知时限**的具体数值与甲方采购 / 安全要求是否一致。
14. **产品尚未正式商用**这一状态是否需要在合同中特别披露或作阶段性约定。

## 四、待确认清单（只列问题，不作法律结论）

> 以下**仅为待确认问题的列举**。本模板不对任何法律法规的适用性、备案义务、
> 合规状态或责任归属作出判断，也不认定任何备案 / 评估要求是否适用。
> 每一项均须由法务结合运营主体、部署方式、数据流向与合同事实逐项确认后，
> 再决定是否需要在正式文本中增加、删除或改写相应条款。

1. 生成式人工智能服务相关备案、算法备案、安全评估等程序是否适用于本项目？适用主体是谁？
   私有化部署、客户内网且通常无外网这一形态，是否会改变上述判断？
2. 简历 / 岗位 JD 评分在招聘场景使用，是否触发算法推荐、自动化决策、就业公平与反就业歧视
   相关的合规要求？需要配置哪些告知、说明、申诉、留痕与人工复核机制？
3. 向第三方模型厂商发送提示词与文档片段，是否构成个人信息出境或跨境提供？
   若适用，需要以何种法律文件、何种程序为基础？由谁负责履行？
4. 客户侧系统的网络安全等级保护定级、备案与测评义务由哪一方承担？
   我方在私有化交付中的配合义务边界如何划定？
5. 「客户作为个人信息处理者 / 委托方、我方作为受托处理者」的划分是否准确？
   全局管理员由部署时环境变量引导创建、可查看全库用户与审计日志，这一事实
   是否影响角色划分、我方的接触数据范围与责任边界？
6. 简历中可能包含的敏感个人信息，其处理依据、单独同意的取得与留存、最小必要范围，
   应由哪一方负责？是否需要在产品侧增加字段级提示或脱敏要求？
7. 日志、审计记录、会话与提问内容的留存期限，是否存在法定下限或上限要求？
   不同类别数据是否应分别设定？由谁配置、如何留痕？
8. 客户提出删除请求时，历史整卷备份中的副本应如何处理、需要多长轮转期、
   是否需要在合同或运维流程中单独约定并告知？
9. 产品是否可能被用于涉及未成年人的场景？若可能，需要增加哪些告知与同意机制？
10. 模型输出的权利归属与使用边界、知识库语料的授权链条，是否需要另有书面约定？
11. 责任限制、间接损失排除与赔偿上限，在选定适用法律下是否可被执行？
12. 争议解决方式（诉讼 / 仲裁）、机构与适用法律，如何与甲方所在地、合同履行地一并考虑？
13. 「第二阶段：能签、尚未正式商用」的产品状态，是否需作特别披露或阶段性约定？
14. 试用与正式许可的差别、以及「License 到期默认仅提示、是否阻断由双方约定并通过配置项启用」
    这一技术实现口径，是否需要在合同中明确约定以避免歧义？
15. 依赖中包含的第三方开源组件（MIT / Apache-2.0 等，具体清单以 `npm ls --all` 或 SBOM 为准）
    与商业许可并存时，交付物中的许可文本、声明义务与 SBOM 应如何满足？
16. 是否需要配套编制个人信息保护影响评估、数据出境相关文件或其他合规文档？
    由谁编制、何时编制、由谁保存？
17. 客户自行将备份外送到异地时，我方是否承担任何义务？
    备份文件含个人信息时，二次委托 / 再转移应如何约定？
18. 服务级别、维护窗口、安全事件通知时限的具体数值，是否与甲方采购与安全要求一致？
19. 现有能力缺口（无 SSO、无多租户、无自动化删除用户全部数据接口、无数据留存自动清理
    定时任务、无异地备份、备份位于客户同一卷内）是否需在合同中作为已知限制逐项披露？
20. 本产品是否会被用于法律、医疗、投资等专门领域？若会，现有免责声明是否充分？
21. 终端用户与求职者应通过何种渠道收到隐私政策告知？由甲方还是乙方履行告知义务？
22. 审计日志、用量配额记录本身是否包含个人信息，其访问、导出与留存规则由谁审批？

## 五、使用与维护

- 本目录文档与软件版本绑定；版本升级、部署形态变化或数据流向变化时须同步复核。
- 填写前请交叉核对 `PRODUCT-GUIDE.md`、`docs/操作手册.md`、`CHANGELOG.md` 中的产品事实，
  避免文档之间出现不一致。
- 法务审核建议留痕（审核人、日期、改动条款），但**不要在模板正文中写入真实姓名**，
  留痕记录应另存于内部流程系统。
- 本说明及四份模板的任何修改，均应重新经过上述法务审核流程。
