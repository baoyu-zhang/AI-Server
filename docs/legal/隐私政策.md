## 一、先说明：谁负责您的信息

欢迎使用 {{产品名}}。这是一套安装在您所在单位自己服务器上的 AI 工作助手，
不是放在公共互联网上的在线服务。

- 本政策里的「**我们**」，指的是本系统的部署运营方 **{{甲方名称}}**——通常也就是
  您的单位或您所在单位的管理部门。您的账号、您输入的文字、您上传的文件，
  都保存在您单位自己的服务器里，由您单位决定保存多久、谁能看到。
- **{{乙方名称}}** 是本软件的交付方。在私有化部署下，交付方**默认无法访问**这些数据；
  只有在您单位书面委托其协助运维、排障，或双方另有约定时，交付方才可能在
  您单位的授权范围内接触到相关信息，并且只能按您单位的指示处理。
- 换句话说：**通常情况下，您的单位是对您个人信息负责的一方（个人信息处理者）**，
  交付方只是被委托提供帮助的一方。双方的具体分工写在
  《数据处理协议》里。如果您对角色划分有疑问，请联系 {{联系邮箱}}。

本政策尽量用通俗的话告诉您：我们收集哪些信息、为什么收集、放在哪里、放多久、
会不会给第三方、怎么保护，以及您能怎么行使自己的权利。

## 二、我们收集哪些信息

在您使用本系统时，可能会涉及以下信息：

| 类别 | 举例 |
| --- | --- |
| 账号信息 | 登录名、口令的校验凭据、账号状态、角色、每日用量额度 |
| 会话与提问 | 您发起的多轮对话、您输入的提问与提示词、系统生成的回答 |
| 您上传的内容 | 简历、岗位 JD、文档、图片等附件，以及加入知识库的资料 |
| 招聘场景相关信息 | 简历与岗位 JD 的评分、匹配结果（仅作辅助参考，见第七节说明） |
| 日志与用量记录 | 登录时间、功能使用记录、按用户日配额的用量统计 |
| 审计记录 | 关键操作（如登录、导出、账号停用、配置变更）的留痕 |
| 本地缓存 | 浏览器为保持登录状态与界面偏好保存的少量数据（见第四节） |

如果您上传的简历或文档里包含他人的信息（例如候选人的联系方式、工作经历），
请确认您有相应的依据再上传，并尽量只提供必要的内容。

## 三、我们为什么使用这些信息

仅用于以下目的：

1. 让您能登录并使用会话、知识库问答、附件、导出打印等功能；
2. 在您主动发起提问时，生成回答、摘要、评分或匹配建议；
3. 在本地建立知识库的检索索引，让问答能引用您单位自己的资料；
4. 保障系统安全：识别异常登录、控制用量、记录关键操作、排查故障；
5. 按您单位的设置进行整卷备份与恢复，防止数据丢失；
6. 在您单位配置了 Webhook 回推时，把结果推送到您单位指定的地址。

我们不会把这些信息用于与本系统功能无关的目的；如用途发生变化，会先更新本政策并告知。

## 四、Cookie 与本地存储

本系统不使用广告类 Cookie。为保持您的登录状态，前端会在浏览器保存会话信息；
为记住界面偏好，也可能使用少量本地缓存。清除浏览器本地数据后，
您可能需要重新登录。这类数据主要保存在您自己的设备上。

## 五、信息保存在哪里、保存多久

- **保存位置**：全部数据存放在 **{{甲方名称}} 自有服务器的单一数据卷**里
  （数据库、图片、上传文件、向量索引、备份、日志均在其中），位于您单位的内网环境，
  通常不连接外网。
- **保存期限**：由您单位自行配置与决定，分别为
  会话与内容 `{{数据留存期限}}`、日志与审计记录 `{{日志留存期限}}`、
  整卷备份 `{{备份保留天数}}`。
  到期或您提出删除后的处理方式见第九节。
- **备份**：备份文件也保存在**同一数据卷**里。是否把备份另行送到异地保存，
  由您单位自行决定和办理。

## 六、会不会提供给第三方

**会，但范围很有限，请您留意：**

为了在您提问时生成回答，本系统会把**您输入的提示词和相关文档片段**
（可能包括简历文本、知识库检索到的片段）发送给第三方大模型服务
**DeepSeek** 进行处理，再把生成的回答返回给您。

- 传输的内容是**提示词与文档片段**，用于模型推理生成回答。
- 您单位**可以自行配置**调用该服务所需的 API Key；未来也**可以替换为本地模型**，
  替换后上述对外发送即可不再发生（具体以实际部署配置为准）。
- **知识库的向量化（embedding）与向量检索完全在您单位内网的本地完成，不会上传。**
- 除了上述模型推理、以及您单位自行配置并授权的 Webhook 回推 / 运维委托外，
  我们不会把您的信息提供给其他第三方用于其自身目的。

涉及上述第三方处理的具体约定，由您单位与交付方在《数据处理协议》中明确，
包括是否需要事先书面同意、以及替换服务方的安排。

## 七、关于 AI 生成内容与招聘场景

系统生成的回答、评分与匹配结果**只是辅助建议**，可能不准确、不完整或有偏差，
**请务必人工复核**后再使用。它们不构成录用或淘汰决定，也不构成法律、医疗、
投资等方面的专业意见。

**招聘场景特别说明**：简历 / 岗位 JD 的评分与匹配结果**仅作辅助参考**，
**最终决定必须由具备资质的人工做出**，系统**不得用于自动淘汰候选人**。

## 八、我们怎么保护您的信息

本系统已具备以下安全措施（括号中是对应机制的说明，方便您了解）：

1. **双重身份校验**：登录会话与 API Key 双重凭证，接口访问需通过校验；
2. **按用户日配额**：为每个账号设置每日用量上限，避免异常滥用；
3. **访问频率限制**：对请求做限流，并对登录失败次数做限制，抵御暴力尝试；
4. **提示词注入防护**：对输入内容做注入攻击防护，降低被恶意指令劫持的风险；
5. **图片链接签名**：图片访问链接带 HMAC 签名，防止被随意拼接访问；
6. **关键操作留痕**：登录、导出、账号停用、配置变更等记入审计日志并落库；
7. **账号停用**：管理员可停用不再使用的账号；
8. **回调安全**：Webhook 回推使用 HMAC-SHA256 签名，并对回调地址做 SSRF 防护校验。

此外，管理员凭据由您单位保管，访问遵循最小权限原则。
需要说明的是，任何系统都无法做到绝对安全，请您也妥善保管自己的账号与口令。

## 九、您的权利与如何行使

您可以就自己的个人信息提出**访问、更正、删除、导出**等请求。

- **行使方式**：请联系本系统的管理员，或提交运维工单
  （渠道：`{{运维工单渠道}}`，也可发邮件至 `{{联系邮箱}}`）。
  由管理员核验身份后按您单位的流程办理。
- **导出**：您单位可通过整卷备份取得数据库与附件的副本；恢复时使用
  完整的备份包，仅取数据库文件会导致图片、附件缺失。
- **删除的现实情况，请您理解**：当前版本**没有自动化的「一键删除某用户全部数据」功能**，
  删除请求需要管理员按运维流程人工处理；系统也**没有到期自动清理的定时任务**。
  另外，**删除不会立刻从历史备份里消失**——整卷备份会按 `{{备份保留天数}}` 天保留，
  历史备份中的副本需等备份到期自然轮转，或在您单位要求下重建备份后才能清除。
  这些时滞与处理方式由您单位与交付方在《数据处理协议》中约定。
- 如果您对处理结果有异议，可通过上述渠道反馈，或联系 `{{数据保护联系人}}`。

## 十、未成年人

如确有涉及未成年人的信息需要处理，相关告知与同意由您单位按其适用要求办理；
具体情况请通过 `{{联系邮箱}}` 咨询。相关要求是否适用、需增加何种机制，
由法务另行确认。
