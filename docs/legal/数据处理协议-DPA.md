## 第一条　角色划分

1.1 双方约定（**该划分须由法务结合实际事实逐条确认**）：

- **甲方为个人信息处理者 / 委托方**：甲方决定个人信息的处理目的、方式、范围、
  保存期限与访问权限，并自行承担相应的告知、同意、合法性基础等义务。
- **乙方为受托处理者 / 受委托方**：乙方仅按照甲方的书面指示、在本 DPA 约定范围内
  处理相关个人信息，不得超出指示或用于自身目的。

1.2 **私有化部署下乙方默认不接触数据（如实写明）**：本产品部署于甲方自有服务器与客户内网，
数据全部存放于甲方单一数据卷（`app.db`、`images/`、`uploads/`、`vector-index/`、
`backups/`、`logs/`），**乙方默认无法访问甲方数据**。

1.3 **可能接触数据的情形（如实写明）**：部署时全局管理员账号由环境变量
（`ADMIN_USERNAME` / `ADMIN_PASSWORD`）引导创建，该账号**可查看全库用户与审计日志**。
若甲方书面委托乙方承担运维、排障、恢复演练或其他现场 / 远程支持，乙方可能在
甲方授权范围内接触到上述数据。此时乙方应遵守最小必要原则、保密义务、
仅按甲方指示处理，并对接触行为留痕。该事实是否影响第 1.1 条的角色划分与责任边界，
**由法务确认**。

1.4 若任何一方角色发生变化，或出现共同处理、独立处理等情形，双方应另行书面确认
并相应修订本 DPA；本模板不对角色认定作结论。

## 第二条　处理范围与指令

2.1 乙方仅可为以下目的处理个人信息：交付、部署、初始化、升级维护、
故障排查、备份 / 恢复协助、安全事件处置，以及甲方书面指示的其他事项。

2.2 处理指令应**以书面形式**（含双方认可的工单、邮件）发出，并载明涉及的数据范围、
目的、期限与期望结果。乙方认为指令可能违反适用要求时，应及时提示甲方，
但是否提示、如何提示及相应后果由法务确认。

2.3 乙方不得将个人信息用于本协议之外的目的，不得自行决定处理目的与方式，
不得向未获授权的人员披露。

2.4 **处理期限**：自 `{{日期}}` 起至本 DPA 终止或甲方书面终止之日止，
具体存续期与终止后处理见第九条。

## 第三条　数据类别与数据主体

3.1 **数据主体**：甲方员工、管理员、经甲方授权使用本系统的其他人员，
以及**求职者 / 候选人**（其信息可能出现在上传的简历、岗位 JD 与评分记录中）。

3.2 **数据类别**：

| 类别 | 内容 |
| --- | --- |
| 身份与账号 | 登录名、凭据校验信息、角色、账号状态、日配额 |
| 会话内容 | 多轮会话、提问 / 提示词、模型回答 |
| 上传内容 | 简历、岗位 JD、文档、图片等附件、知识库语料 |
| 招聘场景结果 | 评分、匹配结果（仅作辅助参考） |
| 日志与用量 | 登录与使用记录、按用户日配额的用量统计 |
| 审计记录 | 关键操作留痕（登录、导出、账号停用、配置变更等） |
| 备份副本 | 整卷备份中包含的上述数据副本 |

3.3 **敏感个人信息（待确认，不作结论）**：简历中可能包含敏感个人信息。
其处理依据、单独同意的取得与留存、最小必要范围、是否需字段级提示或脱敏，
由哪一方负责、如何落实，**须由双方与法务逐项确认后另行约定**；
本 DPA 不作任何认定。

## 第四条　子处理者

4.1 **模型推理子处理者：DeepSeek**。为在用户提问时生成回答，本产品会将
**提示词与文档片段**（可能包括简历文本、用户提问、知识库检索片段）
发送至第三方大模型服务 **DeepSeek**（通过 `@ai-sdk/deepseek` 调用）进行处理。

4.2 **需事先书面同意**：甲方**应事先以书面方式同意**上述子处理安排，
方可启用相关模型推理功能。同意的形式、范围、撤回方式，以及撤回后对功能的影响，
由双方约定并经法务审核。本模板不认定该同意是否充分或是否还需其他程序。

4.3 **可替换**：甲方可自行配置调用所需的 API Key（部署变量 `DEEPSEEK_API_KEY`）；
未来**亦可替换为本地模型**。更换或新增子处理者时，乙方应提前告知甲方，
并按第 4.2 条重新取得书面同意。

4.4 **不上传的部分**：知识库的 embedding（`bge-small-zh-v1.5` 本地模型）
与向量检索（本地向量索引）**完全在甲方内网本地完成，不向任何第三方上传**。

4.5 乙方应确保子处理者承担不低于本 DPA 约定的保护义务；具体合同安排、
子处理者清单的维护与告知方式，由双方另行约定并经法务审核。

## 第五条　技术与组织措施（TOMs）

5.1 乙方已在本产品中实现、并在交付范围内维持下列**技术措施**（对应现有能力）：

1. **双凭证鉴权**：会话（session）+ API Key 双重身份校验；
2. **按用户日配额**：按账号限制每日用量；
3. **限流**：请求频率限制，以及登录失败限流；
4. **提示词注入防护**：对输入做 prompt injection 防护；
5. **图片 URL HMAC 签名**：防止图片资源被未授权拼接访问；
6. **审计落库**：关键操作写入审计日志并持久化；
7. **账号停用**：管理员可停用账号；
8. **Webhook 安全**：HMAC-SHA256 签名校验 + SSRF 防护。

5.2 **组织措施**：最小权限访问、保密义务、按书面工单行事、接触数据留痕、
人员授权与变更管理、运维流程留档。具体制度与执行证据由双方约定。

5.3 **甲方负责的措施（如实写明）**：服务器与网络环境安全、数据卷的存储与访问控制、
管理员凭据保管、账号准入与停用策略、备份外送异地、留存期限配置，
以及内网通常无外网条件下的边界防护。

5.4 **已知缺口（如实写明，不假装已有）**：无 SSO、无多租户、
**无自动化的「删除用户全部数据」接口**（需人工按运维流程处理）、
**无数据留存自动清理定时任务**、**无异地备份**（备份位于甲方同一卷内，
需甲方自行外送）。上述缺口的处置与是否需补充措施，由双方书面确认。

5.5 双方可约定定期复核 TOMs 的有效性；复核周期 `{{复核周期}}` 留待确认。

## 第六条　数据主体请求协助

6.1 甲方负责受理并响应数据主体的访问、更正、删除、导出等请求；
乙方应在合理范围内提供协助（如定位数据、执行导出、按指令删除）。

6.2 乙方收到直接来自数据主体的请求时，应转交甲方，不擅自响应。

6.3 协助方式、响应时限 `{{请求响应时限}}`、工单渠道 `{{运维工单渠道}}`
由双方约定；相关时限要求是否适用由法务确认。

## 第七条　安全事件通知

7.1 一方发现或合理怀疑发生涉及个人信息安全事件时，应及时通知另一方。

7.2 **通知时限：`{{安全事件通知时限}}`（占位，由双方约定并经法务确认）**。
本模板**不设定默认值，也不认定任何法定时限**。

7.3 通知应包含（可按需增减）：事件概况、受影响数据类别与主体范围的初步判断、
已采取的处置与缓解措施、联系人 `{{安全事件联系人}}`。
后续调查与补充通知的安排由双方约定。

7.4 对外通报、向监管报送、向数据主体告知的义务分工与内容审核，
**待法务确认后另行约定**；本 DPA 不作判断。

## 第八条　审计与配合

8.1 乙方应向甲方提供必要的记录与说明，以配合甲方开展合规审查或审计，
范围限于本 DPA 约定的处理活动。

8.2 甲方可利用产品内的审计日志、用量记录与备份清单作为核查依据；
现场审计的方式、频率、费用与保密要求由双方约定。

8.3 审计发现的问题应形成整改清单并留痕；整改期限 `{{整改期限}}` 留待确认。

## 第九条　数据返回、导出、删除与终止后处理

9.1 **导出 / 返回**：甲方可随时通过整卷备份导出客户数据，备份产出为**成对的**
`.db`（数据库）与 `.tar.gz`（含数据库、图片、上传文件、向量索引的完整包）。
**恢复一律使用 `.tar.gz`**；仅恢复 `.db` 会导致图片与附件缺失。

9.2 **删除（如实写明能力边界）**：当前版本**无自动化的「删除用户全部数据」接口**，
删除须按甲方书面指令、由管理员 / 运维**依运维流程人工处理**；
亦无数据留存自动清理定时任务。乙方按指令删除其持有的副本，
甲方数据卷内的数据由甲方运维操作为主。

9.3 **备份中的删除时滞（如实写清楚）**：
整卷备份按 `{{备份保留天数}}` 天保留，保存在甲方**同一数据卷**内。
因此，**删除操作不会立即从历史备份中抹除相关副本**；
历史备份中的副本需**待备份到期自然轮转**，
或在甲方要求下**重建备份**后，才能在新备份中不再包含已删除数据。
该时滞的告知方式、可接受期限、重建备份的责任与费用、以及例外情形，
须由双方书面约定并经法务确认。

9.4 **异地备份**：本产品**不提供异地备份**，备份文件由甲方自行外送到异地。
备份外送过程中涉及的再委托、再转移与安全要求由甲方负责或另行约定。

9.5 **终止后处理**：本 DPA 终止或到期后，乙方应在 `{{终止后处理期限}}` 内，
按甲方书面指令选择返还 / 导出或删除其持有的个人信息副本，
并就可能留存于备份中的副本按第 9.3 条处理。法律要求必须留存的部分、
以及留存依据与范围，**待法务确认**。乙方应就完成情况提供书面说明。

## 第十条　跨境传输（如适用，留占位）

10.1 向境外或构成跨境提供的处理活动，其安排为 `{{跨境传输安排}}`（占位）。

10.2 **本 DPA 不认定**上述模型推理或其他数据流动是否构成个人信息出境 / 跨境提供，
也**不认定**是否需要以及需要履行何种程序、采用何种法律文件。
是否适用、适用主体、所需程序与文件，均**须由法务结合数据流向与实际部署逐项确认**，
并据此决定是否在正式文本中增加相应条款（参见 README 待确认清单第 3、16、17 项）。

10.3 若双方确认适用，应另行签署相应文件并明确责任分工后，相关处理方可进行。

按主协议 / 订单中的责任条款处理。

11.2 赔偿责任上限 `{{赔偿上限}}`、间接损失排除、第三方索赔分担、

本模板不作确定性认定。

11.3 本 DPA 与主协议、用户协议、许可协议冲突时的优先顺序，待法务审核后明确。
