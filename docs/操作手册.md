# {{产品名}} 操作手册（一页纸）

> 面向客户 IT 与管理员 · 对应版本 **1.0.0** · 交付形态：Docker 镜像 + docker compose，
> 部署于客户内网、通常无外网。
> 以下命令均在**离线安装包解压后的目录**下执行；文中 `<...>`、`{{...}}` 均为占位符，
> 示例**不含任何真实口令、密钥或域名**，请替换为实际值后再执行。
> 前置：服务器已安装 Docker Engine / Docker Compose V2。
>
> ⚠️ **离线包里没有源码目录**：`scripts/`、`server/`、`web/` 都在镜像内部，
> 客户机上不能直接执行 `node scripts/setup.mjs` 或 `node server/backup.js`。
> 需要跑脚本时一律用 `docker compose exec app ...` 进容器执行（见第 4 节）。

## 1. 首次部署（照抄执行）

```bash
# 0) 核对架构：必须与 BUILD-INFO.txt 记录的镜像架构（如 linux/amd64）一致
uname -m
cat BUILD-INFO.txt

# 1) 校验交付物完整性，全部 OK 再继续
sha256sum -c SHA256SUMS

# 2) 导入预构建镜像 —— 离线包内【不要加 --build】，无外网无法在线构建
docker load -i image.tar.gz

# 3) 现场生成配置：离线包内只带模板，请手工编辑（不要提交、不要随包转发）
cp .env.example .env
vi .env                      # 填 DEEPSEEK_API_KEY；ADMIN_PASSWORD / IMAGE_SIGN_SECRET 用强随机串
#   参考：openssl rand -hex 24   （生成 ≥12 位强随机口令/密钥）

# 4) 启动（离线包根目录里的 docker-compose.yml，无源码、切勿加 --build）
docker compose -f docker-compose.yml --env-file .env up -d

# 5) 浏览器访问 http://<服务器IP>:3000

# 6) 确认健康状态，期望看到 healthy
docker compose -f docker-compose.yml --env-file .env ps
```

> 三个必须记住的点：
> - **离线包内不要加 `--build`**：镜像已预构建并离线导入，在线构建会拉取依赖而失败。
> - **必须核对镜像架构**：`uname -m` 的结果要与 `BUILD-INFO.txt` 对齐，
>   架构不匹配会反复重启并报 `exec format error`，改 compose 无效，只能重新打包。
> - **`npm run setup` 向导只在有完整源码的构建机上可用**；客户机请用上面的 `cp + vi`。

## 2. 管理员初始账号（重要）

- 初始全局管理员来自 `.env` 的 `ADMIN_USERNAME` / `ADMIN_PASSWORD`，
  由部署时环境变量引导创建，**能看到全库用户与审计日志**。
- **每次启动都会把该账号的密码同步成 `.env` 里的取值**。因此：
  **在后台改密后，必须同步修改 `.env` 的 `ADMIN_PASSWORD` 并重启，否则后台修改会在下次启动时被覆盖。**
- **首次登录立即改密并妥善保管**；改密后按上一条同步 `.env`。请勿把口令写进交付包或提交到仓库。

## 3. 日常账号管理

- 当前为**开放自助注册**；是否收紧注册准入由客户自行决定。
- 管理员在「**管理**」页签可**停用账号**、**设置按用户日配额**，建议按最小权限分配。
- 管理接口强制使用**网页 session**：用 API Key 调用会返回 403（即使该 Key 属于管理员）。
- 常用接口（完整 25 条速查表见随包交付清单或 `PRODUCT-GUIDE.md` 第 5 章）：

```bash
# 列出全部用户（先登录拿到 session token，下面 <token> 为占位）
curl -sS "http://<服务器IP>:3000/api/admin/users" \
  -H "Authorization: Bearer <token>"

# 停用 / 启用账号（disabled 必须是布尔值 true/false）
curl -sS -X PATCH "http://<服务器IP>:3000/api/admin/users/<用户ID>/status" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"disabled": true}'

# 设置按用户每日 Token 配额
curl -sS -X PATCH "http://<服务器IP>:3000/api/admin/users/<用户ID>/quota" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"quotaDaily": 50000}'
```

- 当前**无自动化的「删除用户全部数据」接口**，删除需人工按运维流程处理；
  无 SSO、无多租户、无数据留存自动清理定时任务。

## 4. 备份与恢复

镜像内工作目录是 `/app`，脚本都在容器内。用 `exec app` 执行，不要在宿主机找 `server/`：

```bash
COMPOSE="docker compose -f docker-compose.yml --env-file .env"

# 备份：产出【成对】的 .db 与 .tar.gz（含数据库 + 图片 + 上传文件 + 向量索引）
$COMPOSE exec app node backup.js

# 查看 / 校验备份（文件名从上一步输出或 --list 取）
$COMPOSE exec app node restore.js --list
$COMPOSE exec app node restore.js --verify <备份文件.tar.gz>

# 恢复（会覆盖现有数据，执行前请先另做一次当前备份；--force 会把原目录改名留底）
$COMPOSE exec app node restore.js --restore <备份文件.tar.gz> --force
$COMPOSE restart app
```

> - **恢复一律用 `.tar.gz`**：只恢复 `.db` 会导致图片、附件全部丢失（页面图片全裂）。
> - 备份**保存在客户自己的同一数据卷内，本产品不提供异地备份**，
>   **请客户自行定期把备份外送到异地**保存。
> - 删除操作不会立即从历史备份中抹除，需等备份到期自然轮转或重建备份。

## 5. 换品牌 / 装许可（无需重建镜像）

品牌与许可文件都放在**数据卷 `/app/data`** 里，改完重启容器即生效，镜像与 SHA256SUMS 不变。

```bash
COMPOSE="docker compose -f docker-compose.yml --env-file .env"

# 1) 以包内模板为基础改成客户自己的值
cp templates/branding.example.json ./branding.json
vi ./branding.json

# 2) 拷进容器的数据卷（Docker Compose V2 的 cp 子命令）
$COMPOSE cp ./branding.json app:/app/data/branding.json
$COMPOSE restart app
```

`branding.json` 常用字段：

| 字段 | 作用 |
| --- | --- |
| `productName` / `shortName` | 浏览器标签页标题 / 窄屏顶栏短名 |
| `companyName` / `footer` | 登录页页脚的客户名与版权信息 |
| `loginTitle` / `loginSubtitle` | 登录卡片的主标题与副标题 |
| `logoUrl` / `faviconUrl` | 客户 Logo 与浏览器图标（只接受 http(s) 或站内路径） |
| `termsUrl` / `privacyUrl` / `supportUrl` | 用户协议、隐私政策、帮助链接，填了才显示 |
| `terminology` | 行业术语字典：`candidate` / `resume` / `job` / `knowledge`。主链是行业中立的，这里只换界面显示文字，后端枚举不变 |
| `panels.candidates` | 设为 `false` 可整块隐藏「候选人」页签（非招聘场景） |

许可文件（可选）：由交付方用 `npm run license:generate` 生成 `license.json` 后交给客户，
拷到 `/app/data/license.json`（命令同上，把文件名换掉）；部署侧 `.env` 需配同一个
`LICENSE_SIGN_SECRET`。**默认到期 / 超额只在登录页提示、不阻断使用**；
只有合同约定停用、且 `.env` 里设 `LICENSE_ENFORCE=1` 时，才会拒绝新登录（已登录会话不受影响）。
直接把 `templates/license.example.json` 改名当正式许可使用会导致签名校验失败，请勿这样做。

## 6. 常见故障速查

| 现象 | 排查要点 |
| --- | --- |
| 401 未登录 | 会话已过期或未带凭证；重新登录，接口调用需携带有效 session 或 API Key |
| 端口不通 | `docker compose -f docker-compose.yml --env-file .env ps` 看容器是否运行；检查 3000 端口映射、服务器防火墙 / 安全组 |
| 知识库检索无结果 | 离线 embedding 模型未预置（应在构建机上跑 `scripts/prefetch-model.mjs` 并重新打包），或向量索引为空（需先导入语料） |
| 忘记管理员密码 | 修改 `.env` 的 `ADMIN_PASSWORD` 后重启（启动会把该账号口令同步为 env 值） |
| 改了品牌但页面没变 | 确认文件确实拷进容器：`docker compose ... exec app cat /app/data/branding.json`；改完必须 `restart app`；浏览器强刷一次（接口返回 `no-store`） |
| 登录页显示「许可签名不匹配」 | `LICENSE_SIGN_SECRET` 与签发许可时用的不一致，或误把示例模板当成正式 `license.json` |
| 容器反复重启 / `exec format error` | 镜像架构与客户机 CPU 不匹配，核对 `uname -m` 与 `BUILD-INFO.txt`，需重新打包 |
